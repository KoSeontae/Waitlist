# 예약 신청 탐색 측정 (2026-11-27)

본 측정의 동시 사용자 수를 고르기 위한 탐색이다. 조건마다 1회만 측정했으므로 기준선으로 쓰지 않는다.

## 환경

- MacBook, Intel i5-7267U (물리 2코어, 논리 4), 메모리 8GB, 전원 연결
- Docker에 CPU 4, 메모리 4GB. PostgreSQL 16, `waitlist_load` DB
- 앱: `java -jar`, JDK 21, 힙 1GB, 커넥션 풀 10. 동시성 보호 없음
- 실행 중인 컨테이너는 `waitlist-postgres`뿐. IntelliJ와 Chrome은 종료. Claude 앱과 로컬 PostgreSQL 14(유휴)는 실행
- 시작 직전 유휴 CPU 약 75%
- 조건당 5,000건, 프로필 `perf`(모든 요청 성공), 워밍업 3,000건

## 해석

- 처리량은 동시 5-10명에서 한계(분산 약 160-170 req/s)에 닿는다. 이후에는 응답 시간만 늘어난다.
- 동시 5명은 커넥션 풀(10)보다 적은데도 요청당 시간이 14ms에서 31ms로 늘었다. 한계의 주된 원인은 풀보다 CPU로 보인다(추정).
- k6는 0.14코어 이하를 써서 부하 생성기가 병목일 가능성은 낮다.
- 집중(hot)은 DB CPU가 분산보다 높다. 회차 하나에 예약이 5,000건까지 쌓여 건수 조회 비용이 커지기 때문으로 보인다(추정).
- hot 50명의 처리량 하락(130.6)은 100명에서 회복돼, 반복 측정 전에는 의미를 판단하지 않는다.
